    Codex 桌面版如何配置 WPS MCP：从连接到生成文档、表格和 PPT

    4 minute read

    Published: August 28, 2026

    这篇文章讲的是 Codex 桌面版 / Codex 图形界面 里如何配置 WPS MCP，并用它生成 WPS 可以打开的文档、表格和演示稿。

    先说明一个容易混淆的点：这里说的不是普通 ChatGPT 聊天窗口，也不是让你一直在终端里敲命令。我们要做的是在 Codex 的桌面或 IDE 界面里打开 MCP 配置，把 WPS MCP Server 接进去。配置完成后，你只需要在 Codex 对话里说“帮我生成一份周报”或“帮我做一个销售数据表”，Codex 就能调用 WPS MCP 工具完成文件生成。

    MCP 可以理解成 AI 的“工具插座”。Codex 负责理解你的需求，WPS MCP 负责把需求变成真实文件，例如 .docx、.xlsx 和 .pptx。

    一句话讲清楚你在配置什么

    你不是在给 WPS 装一个传统插件，而是在给 Codex 增加一个“本地办公工具箱”。

    01 你提出需求

    例如：生成周报、整理 Excel、制作 3 页 PPT。

    02 Codex 选择工具

    判断应该调用创建文档、写单元格还是生成幻灯片。

    03 WPS MCP 执行

    本机 Python 服务把任务转成具体的文件操作。

    04 WPS 打开结果

    你在工作目录里看到生成好的 .docx、.xlsx、.pptx。

    这里的关键是：Codex 桌面版并不是“直接控制 WPS 界面”。它先通过 MCP 调用一个本地工具，再由这个工具生成 WPS 可以打开的标准 Office 文件。

    本文采用的 WPS MCP 方案

    目前 WPS MCP 大致有两类：

    方案适合谁特点
    文件级 WPS MCP新手、跨平台用户、主要想生成文档直接生成 .docx、.xlsx、.pptx，上手简单
    Windows COM 自动化Windows 用户、想操作已打开的 WPS 窗口能控制真实 WPS 应用，但依赖 Windows、WPS 安装和 COM 环境

    本文使用更适合入门的文件级方案：Xiao-rx/wps-mcp-server。它通过 python-docx、openpyxl、python-pptx 生成 Office 标准文件，所以 WPS 和 Microsoft Office 都能打开。

    如果你后续需要“修改当前打开的表格”“操作图表”“导出 PDF”“运行宏”，再考虑 hinora/office-mcp 这类 Windows COM 自动化方案。它更强，但不适合作为第一篇入门教程。

    配置前准备

    先准备四样东西：

    Codex 桌面版能正常登录，并能进入 Codex 工作区或编码代理界面。
    Python 3.10+用于运行 WPS MCP Server。路径最好固定，不要频繁移动。
    WPS MCP 文件夹下载并固定保存 wps_mcp.py 这个服务脚本。
    输出工作目录专门保存 AI 生成的办公文件，避免误写其他目录。

    推荐目录结构如下：

    Documents/
  mcp-servers/
    wps-mcp-server/
      wps_mcp.py
      requirements.txt
      .venv/
  wps-mcp-workspace/
    weekly_report.docx
    ai_office_demo.xlsx
    product_intro.pptx

    如果你不熟悉 Python 环境，可以把准备工作理解成两句话：

    1. 让电脑能运行 wps_mcp.py。
    2. 让这个 Python 环境里安装好 mcp、python-docx、openpyxl、python-pptx。

    这一步可以按 WPS MCP 项目 README 操作，也可以让懂 Python 的同学帮你处理一次。后面在 Codex 桌面版里使用时，不需要你每次手动运行这些东西。

    第一步：打开 Codex 桌面版的 MCP 配置

    在 Codex 桌面版或 Codex 图形界面中，按这个路径找：

    Open

    右上角齿轮或设置入口

    Settings

    进入 Codex Settings

    MCP

    选择 MCP settings 或 Open config.toml

    官方文档说明，Codex 的 MCP 配置保存在 config.toml 中。通常是用户级配置：

    ~/.codex/config.toml

    如果你在某个项目里使用项目级配置，也可能是：

    .codex/config.toml

    新手建议先用用户级配置。这样你在 Codex 桌面版里每次开启新会话，都能看到同一套 WPS MCP 工具。

    第二步：写入 WPS MCP 配置

    打开 config.toml 后，加入一个 [mcp_servers.wps] 配置块。

    macOS 示例：

    [mcp_servers.wps]
command = "/Users/<你的用户名>/Documents/mcp-servers/wps-mcp-server/.venv/bin/python"
args = ["/Users/<你的用户名>/Documents/mcp-servers/wps-mcp-server/wps_mcp.py"]
env = { WPS_WORKSPACE = "/Users/<你的用户名>/Documents/wps-mcp-workspace" }
startup_timeout_sec = 20
tool_timeout_sec = 60

    Windows 示例：

    [mcp_servers.wps]
command = "C:\\Users\\<你的用户名>\\Documents\\mcp-servers\\wps-mcp-server\\.venv\\Scripts\\python.exe"
args = ["C:\\Users\\<你的用户名>\\Documents\\mcp-servers\\wps-mcp-server\\wps_mcp.py"]
env = { WPS_WORKSPACE = "C:\\Users\\<你的用户名>\\Documents\\wps-mcp-workspace" }
startup_timeout_sec = 20
tool_timeout_sec = 60

    每一行的意思如下：

    [mcp_servers.wps]给这个 MCP Server 起名叫 wps，之后 Codex 会用这个名字识别它。
    command指向能运行 WPS MCP 的 Python 程序。建议写绝对路径。
    args指向 WPS MCP 的服务脚本，也就是 wps_mcp.py。
    env给服务传入工作目录。本文用 WPS_WORKSPACE 限制输出位置。
    startup_timeout_sec允许服务启动慢一点，避免第一次加载依赖时超时。

    注意，Codex 使用的是 TOML，不是 Cursor 或 Claude Desktop 常见的 JSON。不要写成：

    {
  "mcpServers": {
    "wps": {}
  }
}

    Codex 需要的是：

    [mcp_servers.wps]

    这个差异非常重要。很多连接失败不是 WPS 的问题，而是把 JSON 配置粘进了 Codex 的 TOML 文件。

    第三步：重启 Codex 桌面版

    保存 config.toml 后，退出当前 Codex 会话，再重新打开 Codex 桌面版。

    重启的原因很简单：Codex 通常在新会话开始时读取 MCP 配置。你刚保存的 wps 工具箱，需要重新进入会话后才会被加载。

    你可以在新对话里直接问：

    请检查当前是否可以使用 wps MCP。先不要创建文件，只告诉我你能看到哪些 WPS 相关能力。

    如果配置成功，Codex 应该会理解它可以通过 WPS MCP 创建文档、读写表格、生成演示稿等。如果它说找不到 wps 或找不到相关工具，就去看后面的排错部分。

    第四步：设置一个安全的工作目录

    强烈建议把所有 AI 生成的办公文件都放进一个固定目录，例如：

    Documents/wps-mcp-workspace/

    为什么要这么做？

    • 你知道生成的文件在哪里。
    • 出错时容易删除重来。
    • 不会把 AI 写入权限扩散到整个电脑。
    • 后续想备份或同步，也只需要处理一个文件夹。

    第五步：简单应用 1，生成一份 WPS 周报

    在 Codex 桌面版的新对话里输入：

    请使用 wps MCP 创建一份 WPS 文字文档。

文件名：weekly_report
标题：AI Office Weekly Report
结构：
- Summary
- Progress
- Next Steps

每个部分写一段简短内容，语气正式、适合作为工作周报。
完成后告诉我文件保存路径。

    你要观察三个结果：

    1. Codex 是否明确说它调用了 WPS MCP。
    2. 工作目录里是否出现 weekly_report.docx。
    3. 用 WPS 打开后，标题和段落是否正常。

    如果这一步成功，说明“Codex 桌面版 -> WPS MCP -> WPS 文件”的基础链路已经跑通。

    第六步：简单应用 2，生成一个销售表格

    再输入：

    请使用 wps MCP 创建一个 WPS 表格。

文件名：sales_brief
Sheet 名称：Summary
第一行字段：Month, Revenue, Cost, Profit
写入 7 月、8 月、9 月三行示例数据。
Profit 使用 Revenue - Cost 的公式。
完成后告诉我文件保存路径。

    打开生成的 sales_brief.xlsx，重点检查：

    • 表头是否在第一行。
    • 示例数据是否按月份排列。
    • Profit 列是否写入公式或计算结果。

    这类任务最适合 WPS MCP：结构清楚、字段明确、结果容易验证。

    第七步：简单应用 3，生成一个三页 PPT

    继续在 Codex 桌面版中输入：

    请使用 wps MCP 创建一个 WPS 演示文稿。

文件名：product_intro
主题：AI Office Automation
页数：3 页
第 1 页：标题页
第 2 页：为什么使用 MCP
第 3 页：WPS 自动化流程

每页放 3 个简短 bullet points。
完成后告诉我文件保存路径。

    第一次生成 PPT 时，不要要求太复杂的排版。先确认能生成文件、能打开、内容结构正确。之后再逐步要求它优化标题、调整顺序或补充内容。

    入门阶段的判断标准
    • 能生成文件，比一开始就追求精美排版更重要。
    • 能稳定重复生成，比一次性做复杂大文件更重要。
    • 能明确保存路径，比让文件散落在电脑里更重要。

    为什么 Codex 桌面版也要写 config.toml

    这点看起来“不像桌面软件”，但它是 MCP 的核心设计。

    Codex 桌面版负责界面和对话，config.toml 负责告诉 Codex：有哪些外部工具可以用、怎么启动这些工具、工具的工作目录在哪里。官方文档也说明，Codex 的 MCP 配置通过 [mcp_servers.<server-name>] 这样的 TOML 表来声明。

    Codex Desktop读取设置
    config.toml
    WPS MCP暴露工具
    Local Files
    WPS Office打开结果

    所以，桌面版并不是不用配置，而是不需要你把使用过程放在命令行里。配置只做一次，之后的使用都可以回到图形界面对话中完成。

    更稳定的提示词写法

    建议用“五段式”描述办公任务：

    请使用 wps MCP 生成一个 WPS 表格。

目标：整理一个三个月销售简报。
文件名：sales_brief_q3
结构：
- Sheet 名称：Summary
- 字段：Month, Revenue, Cost, Profit, Margin
- 写入 7 月、8 月、9 月三行示例数据
- Profit = Revenue - Cost
- Margin = Profit / Revenue
输出：保存到 WPS_WORKSPACE。
验证：完成后告诉我文件名、保存路径和主要字段。

    这样写比“帮我做个表”稳定很多，因为 Codex 不需要猜文件名、字段、公式和输出位置。

    常见问题

    1. Codex 桌面版里看不到 WPS MCP

    通常是以下原因：

    • config.toml 没有保存。
    • 配置块写成了 JSON，而不是 TOML。
    • [mcp_servers.wps] 拼错了。
    • command 或 args 路径不存在。
    • 修改配置后没有重启 Codex 会话。

    2. Codex 说 Python 模块不存在

    这说明 command 指向的 Python 环境里没有安装 WPS MCP 需要的包。重点检查这个 Python 环境是否能导入：

    mcp
python-docx
openpyxl
python-pptx

    不要只看电脑里“有没有 Python”，要看 config.toml 里那条 command 指向的 Python 是否安装了这些包。

    3. 文件生成了，但不知道去哪了

    看 WPS_WORKSPACE。如果你没有设置这个环境变量，示例项目可能会使用默认目录。为了避免混乱，建议始终显式设置：

    env = { WPS_WORKSPACE = "/你的/固定/输出目录" }

    4. 它能生成文件，但不能编辑我当前打开的 WPS

    这是正常的。本文使用的是文件级 WPS MCP，它主要操作文件，不是遥控当前窗口。

    如果你要控制“当前打开的 WPS 表格”或做复杂图表、导出 PDF、宏操作，需要 Windows COM 自动化方案。但这类方案更依赖系统环境，建议等文件级 MCP 跑通后再尝试。

    5. 安全上要注意什么

    MCP Server 是本地可执行工具，不是普通提示词。建议遵守三个原则：

    • 只使用你信任的 MCP Server。
    • 输出目录固定在 WPS_WORKSPACE。
    • 不要把包含私人路径或密钥的 config.toml 上传到公开仓库。

    最后总结

    Codex 桌面版配置 WPS MCP 的重点不是记命令，而是理解这个关系：

    Codex 桌面版 -> config.toml -> WPS MCP Server -> WPS 文件

    配置只需要做一次。之后你就可以在 Codex 桌面版里直接用自然语言生成周报、表格和 PPT。入门时不要追求复杂排版，先确保三件事稳定：能连接、能生成、能找到文件。
