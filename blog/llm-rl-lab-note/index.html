    LLM RL Lab：奖励如何一点点改变回答的概率

    Published: September 18, 2026

    大模型强化学习的讨论里，经常会出现这样一条描述：让模型生成回答，对回答打分，再用奖励优化模型。这条线很容易理解，但一旦继续问“分数怎么变成参数变化”，中间就会冒出一串新的名词：advantage、PPO、GRPO、KL、clipping。

    我想把这一段接起来。一个回答拿到高分，并不等于它的概率会立刻被推到最高；采到了哪些回答、分数相对于谁更高、更新幅度受到什么限制，都会影响结果。

    于是我做了 LLM RL Lab。它从预训练、SFT 的背景走到 rollout、reward、policy update 和 evaluation，再把其中的一次更新展开。页面延续这个系列的玻璃面板、平滑动画和 KaTeX 公式，但核心是一个可以实际计算、重复运行的小实验。

    把一个大问题缩小到四种回答

    真实语言模型的动作空间非常大，一段回答又包含许多 token。为了看清奖励怎样影响概率，我先把问题缩小成四种预先给定的完整回答，策略只需要决定选择它们的概率。

    这个取舍让每一步都能被展示出来：按旧策略采样，查到对应奖励，计算优势，构造目标函数，再通过梯度改变各个回答的 logit，得到新的 softmax 概率。这里的采样、概率比、裁剪目标、KL 和梯度更新都是实际计算的；页面没有下载或训练一个真实 LLM。

    小策略当然不能覆盖完整模型训练，但它保留了一个重要的连接：奖励怎样通过优化目标，改变下一次更可能出现什么回答。很多时候，先把这个连接算清楚，比一开始就面对数十亿参数更容易建立理解。

    奖励来自哪里，会改变我们在优化什么

    实验准备了三种任务。

    Math verifier 使用 3x + 2 = 11，在预定义候选中，正确答案得 1，错误答案得 0。JSON verifier 要求用带有 answer 字段的 JSON 回答 17 + 25；只有合法 JSON 且答案是数值 42 的候选得 1。它提醒我们，任务要求可能同时包括内容和输出格式。

    Preference reward 则围绕“向初学者简短解释 KV Cache”，给候选回答设置公开的准确性与清晰度示例分。这个评分表用于展示偏好信号，没有一个训练过的 reward model 在背后评价任意文本。

    这几种任务也帮助区分两类名称。RLHF、RLVR 主要说明反馈从哪里来；PPO、GRPO 主要说明怎样利用反馈更新策略。知道奖励来源，并不能单独确定优化方法。类似地，DPO 的典型偏好优化流程也不需要照搬这里的在线采样环节。

    同一个奖励，减去谁以后才算“好”

    有了奖励，下一步还要得到优势。它表达的是当前回答相对于某个基准好多少，而不只是回答本身得了几分。

    项目里的 PPO 分支采用一个便于核对的单步基准：旧策略在全部四个候选上的精确期望奖励。每个采样回答的奖励减去这个基准，就得到学习信号。真实 PPO 通常需要训练 critic，并使用 GAE 等方法；这里没有模拟那些额外过程。

    GRPO 分支则在同一组采样内部比较，减去组内平均奖励，再按组内标准差归一化。因此，同一个回答是否“相对更好”，也和这次一起采到的其他回答有关。

    保持随机种子和 Group size 不变，切换 PPO 与 GRPO，可以在同一批采样上观察两种基准带来的差异。再点击 Resample group，就能看到有限采样如何改变学习信号。按概率采样允许重复，因此一组里出现相同回答是正常现象。

    如果一组回答奖励完全相同，GRPO 的组内优势会变成零。这时奖励部分没有提供偏好方向；如果策略已经偏离参考策略，KL 项仍可能影响更新。这个情况让我觉得很有启发：分数存在，不代表样本之间一定提供了足够的比较信息。

    观察概率真正动起来

    按 Next step 向前走，奖励和优势先出现，然后才进入策略更新。页面保留六次实际更新的轨迹，可以对照新旧回答概率，而不只是看到一个“训练完成”的标签。

    截图使用 Math verifier、GRPO、seed 42、组大小 8，裁剪参数为 0.2、KL 系数为 0.05、学习率为 0.6。在这组条件下，全部候选空间的期望奖励从约 0.378 变为 0.466，参考策略 KL 最终约为 0.0212。

    这里的期望奖励是把四个候选的奖励按当前概率加权得到的，可以精确计算。它不是独立测试集得分，也不能被解读成模型推理能力提升了多少。更换采样、学习率或其他设置，轨迹也会改变；有限样本和裁剪目标并不保证每一步都单调变好。

    裁剪与 KL，分别在约束什么

    理解更新时，有两个参照很容易混在一起。

    概率比使用的是“当前策略”和“生成这批样本时的旧策略”。裁剪观察这一个比值：当优势为正时，过度提高某个回答的概率，超过上界的部分不再带来更多 surrogate 收益；当优势为负时，则要观察下界一侧。

    这是一种有方向的目标裁剪，不能理解成把最终概率硬性锁进某个范围。页面的 Clipping explorer 可以手动改变概率比，并切换优势正负。尤其是在负优势下，把比值移到下界以下，再看目标怎样变化，能帮助纠正“超出区间就一律截断”的直觉。

    KL 则比较当前策略与固定的参考策略，控制更新后离参考分布有多远。旧策略用于这批采样的概率比，参考策略用于偏离惩罚；即使某次实验起点相同，它们在计算中承担的角色也不同。

    改变 KL 系数、学习率或组大小后，项目会重置轨迹，避免把不同设置的阶段混成一次实验。我更建议一次只改一个参数，再回放完整过程。这样更容易判断，是采样变化了、学习信号变化了，还是同一个信号被更新得更用力了。

    让“根据反馈学习”变得具体

    这个实验没有 token 级的信用分配，没有 critic 训练，也没有分布式 rollout。真实 LLM 的 PPO 和 GRPO 还涉及序列长度、归一化和 KL 估计等细节，因此不能用这里的曲线给两种算法做性能排名。

    但这个小版本已经让我更容易解释一件事：奖励只是学习链路中的一个环节。样本怎样获得，优势怎样计算，更新受到什么限制，最后又检查什么指标，必须接在一起看。

    如果说前面的 Transformer 和推理实验是在追踪信息如何流动，这个项目追踪的就是反馈如何改变行为。看到几个回答的概率确实因为一次可解释的计算而改变，“强化学习”才从一个宽泛的名字，落到了一段可以一步步检查的过程里。
