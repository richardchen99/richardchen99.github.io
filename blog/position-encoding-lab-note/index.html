    Position Encoding Lab：看见位置如何改变 Attention

    Published: September 18, 2026

    做完 Transformer Architecture Lab 之后，我一直想把其中几个很容易一笔带过的环节再展开一点。位置编码就是一个。

    我们通常会说，Attention 需要额外的位置信息，才能知道词的顺序。这句话没有错，但它还没有回答我真正好奇的问题：位置信息究竟加在了哪里？为什么有的方法给向量做加法，有的方法让向量旋转，还有的方法只改注意力分数？如果把同一句话整体往后挪，词之间的关系应该保持多少，又会改变多少？

    于是我把这个问题单独做成了 Position Encoding Lab。它延续了前一个项目的浅色玻璃面板和逐步计算视图，不过这一次，观察的重点收到了一个更小的地方：同一组内容向量，怎样因为位置规则不同，得到不同的 Attention。

    先把“位置”从一句话里拿出来

    项目里准备了两个句子，把 it 与 animal、report 放在不同距离上。句子给实验一个容易理解的背景：当我们在处理一个代词时，它与前面某个词之间隔了多少位置？

    不过，这里的词并不代表模型已经学会了指代关系。实验使用固定的八维内容向量，词语只是帮助定位 Query 和 Key。这样安排，是为了尽量把内容本身的变化固定住，让位置规则成为主要的观察对象。否则热力图变了，我们很难判断是句意、训练权重，还是位置造成的。

    操作时，可以先选择一个 Query，再点击句子里的词作为 Key，然后用 Next step 依次看原始向量、位置变换、点积与缩放、softmax。向量图展示一对维度的几何关系，数值面板则保留完整分量。几何图适合建立直觉，数值轨迹适合检查这个直觉是否站得住。

    三种方法，把位置放在三个不同的地方

    Sinusoidal 的入口最直接：把由正弦、余弦构成的位置向量加到内容向量上。同一个词出现在不同位置，参与后续计算的向量就不同。在这个实验里，Q/K 投影采用恒等映射，因此可以直接看清相加前后的变化。

    这里有个值得停一下的细节。纯位置向量之间的点积具有与相对距离相关的结构，但加入内容以后，还会出现内容与位置之间的交叉项。所以，“使用正弦位置编码”并不意味着“整个注意力分数只取决于相对距离”。把这两句话分开，许多看起来矛盾的现象就容易理解了。

    RoPE 把位置写进旋转角度。每一对维度都相当于一个小平面，Query 和 Key 根据各自的位置旋转；不同维度对使用不同频率。旋转不改变向量的长度，却会改变两者的夹角，从而改变点积。它很适合用动画解释，因为移动位置时，真正变化的是方向。

    ALiBi 则在注意力分数上加入距离偏置。在当前的因果窗口里，历史 Key 离 Query 越远，受到的负偏置越大；Head slope 决定这种惩罚有多强。增大斜率，可以看到分布更倾向附近的位置，但内容匹配仍在参与竞争，距离并不是唯一因素。

    这三种方法并排出现时，我最想让人注意到的，是位置信息进入计算的位置不同。它们都在处理顺序问题，却不需要用同一种方式改变向量。

    把两个位置一起往后移

    整个项目里，我最喜欢的控件是 Shift both positions。

    先保持 RoPE，选中位置 5 的 Query 和位置 1 的 Key，然后把两者一起向后移动 24 个位置。两根向量都会继续旋转，但它们之间的位置差仍然是 4。在内容向量和频率规则固定的条件下，共同增加的旋转会在点积里抵消，因此前后得分应当一致，误差只剩数值计算精度。

    再切换 Sinusoidal，重复同样的操作。由于内容和位置相加后的交叉项通常也会变化，严格的平移不变性一般不成立。切到 ALiBi，则可以观察相同距离如何保留相同的线性偏置。

    这个小实验让“绝对位置”和“相对位置”不再只是两个术语。我们真的动了绝对位置，同时保留距离，再检查结果中哪些量没有变。对我来说，这种控制变量的操作，比只记住某种方法属于哪一类更有帮助。

    从一对向量，回到一整行 Attention

    单个 Query–Key 的分数还不是最终的注意力权重。softmax 会让当前 Query 对所有可见 Key 的分数一起竞争，因此只盯着一对向量，有时会漏掉分布层面的变化。

    页面下方的 Three views, one attention row 把三种方法放进同一个因果窗口，展示完整的一行注意力分布。可以换成长句案例，固定 Query，再改变 Key、频率基底或 ALiBi 斜率，把几何视图里的变化与最终分布对应起来。

    这里没有一张“谁更好”的排名表。某一列权重更高，只能说明当前向量和参数下的计算结果，不能说明某种位置编码更懂这句话。尤其是 RoPE 的平移性质，并不能直接证明一个真实模型在更长上下文里仍然表现良好；训练长度、频率设置、内容分布和模型参数，都会进入那个更大的问题。

    把一个局部问题做得足够清楚

    这个项目仍然用 React、TypeScript 和 Vite 实现，动画负责把计算阶段连起来，KaTeX 负责呈现公式。所有计算都在浏览器本地完成，不需要模型 API。相比接入一个很大的模型，我更在意这个版本能不能让人复现一个变化，并解释它为什么出现。

    写这个实验时，我也更清楚地意识到：“我知道 RoPE 是旋转位置编码”和“我能解释共同平移后哪个量保持不变”，其实是两种不同程度的理解。前者给我们一个名字，后者让这个名字变成可以推导、操作和检查的对象。

    如果你第一次打开它，我建议先做一次共同平移实验，再回到三种方法的并排视图。先抓住一个小现象，再去读公式，位置编码会具体很多。
